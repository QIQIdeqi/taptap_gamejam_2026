### 第二轮交互BUG修复（commit `0eb8225`）

### 第三轮：真正根因 _screenLayer（commit `0f8e0ee`）
- **前两轮只修了 `_screenPanel`，漏了中间层 `_screenLayer`**（SceneManager.lua:275 初次进入 + :346 翻页重建，两处定义）。它是交互按钮的直接父节点，全屏 Panel 默认消费 click，导致交互按钮 onClick 永不触发。
- **现象吻合**：翻页按钮挂 `_screenPanel`（已修）能点；交互按钮挂 `_screenLayer`（未修）不能点；hover 高亮正常（pointerEnter 不受 Panel 拦截影响）。
- **修复**：两处 `_screenLayer` 均加 `pointerEvents = "box-none"`；并把 item/exit 按钮的 onClick 从「事后赋 `btn.props.onClick`」改为「构造时传入」（对齐 MenuSystem 已验证有效的写法）。
- **排查方法论**：对比能工作的组件（MenuSystem）与失效组件（SceneManager）的写法/挂载层级差异，比猜测有效。

### 第四轮：真正根因 position="absolute"（commit `b47b2c0`）✅ 已验证修复
- **决定性根因**：`_makeItemBtn`/`_makeExitBtn` 创建的按钮**缺少 `position = "absolute"`**。此引擎（Yoga 布局）中非 absolute 定位的 widget **无法接收 click**（hit-test 限制），但 `onPointerEnter/Leave` 仍正常 → 解释「hover 高亮有、click 无」的矛盾现象。
- **修复**：item/exit 按钮均加 `position = "absolute"`（对齐已可用的翻页按钮写法），并加 `[SM DEBUG] item/exit clicked` print。
- **验证**：runtime.log 出现 `item clicked: desk`、`item clicked: bookshelf`，onClick 确认触发；且物件属 office 序章场景，印证序章起点问题也已解决。
- **经验**：`pointerEvents` 不是根因；此引擎中 **absolute 定位是可点击的前提条件**。排查 UI 点击失效优先查：①absolute ②父层 pointerEvents ③zIndex 遮挡。
- **诊断技巧**：给 onClick 加 print 日志，用 runtime.log 确认事件是否真的触发，避免连续猜测式修复。

### Exit 回调修复（commit `8dcc1a1`）部署中
- **根因**：main.lua 调 EnterScene 时 onExit 传 nil → M.onExit=nil → exit 按钮 onClick 永不执行场景切换。
- **第一版修复错误**：用了嵌套递归匿名函数 → 每次 EnterScene 都调 UI:Init()（SceneManager.lua:84）→ 引擎报 "UI.Init() called twice without UI.Shutdown()" → UI 状态崩溃 → 所有按钮失效。
- **最终修复**：定义统一 sceneExitCallback 函数引用，所有 EnterScene 共享，避免重复 Init。

### main.lua "M 为 nil" 报错修复（commit `9429faa`）✅ 已验证
- **报错**：`[string "main"]:101: attempt to index a nil value (global 'M')`（Start 函数内）
- **根因**：上一轮修 exit 回调时误用 `M._sceneExitCallback`，但 **main.lua 是主入口脚本、不是模块，没有 `local M = {}`**，故 M 为 nil。
- **修复**：顶部声明 `local sceneExitCallback = nil`，三处引用（定义 + 2 处 EnterScene 调用）全部改为 `sceneExitCallback`。
- **验证**：runtime.log 搜 error/attempt to index/nil value/stack traceback 全 0 匹配；exit 跳转生效（exit clicked 紧跟 _EnterScreens done）；翻页与交互正常。
- **教训**：main.lua 无 M 命名空间，新增回调须用 local 变量；SceneManager/GameData 等模块才有 `local M = {}`。
- **已知非阻塞 WARNING**：`UI.Init() called twice without UI.Shutdown(), ignored`（EnterScene 内重复调 UI:Init()，引擎自动忽略，不影响功能）。

### 引擎 onClick 重复派发修复（commit `8a5bc14`）部署中
- **根因（引擎级 bug）**：此引擎会把**同一次点击重复派发 onClick**。日志铁证：一次 exit 点击产生 6+ 条 `exit clicked` + 6 次 `_EnterScreens done`；`_SwitchScreen dir=right cur=s3` 连续两条而中间无 `btnRight clicked`。翻页早已因此加过防抖，但 exit/物件交互未加。
- **后果**：单次点击 exit → 反复 EnterScene → 反复 UI:Init() → UI 状态异常/场景错乱，表现为"点了没用"。
- **修复**：① `sceneExitCallback` 加「同帧 + 同目标」防抖；② `_onItemInteract` 加「同帧 + 同物件」防抖；③ `ShowClueBanner` 先销毁旧横幅防叠加（`M._activeBanner`）。
- **引擎通性结论**：**此引擎所有 onClick 回调都需自行加防抖**，不能假设一次点击只触发一次。
