## 关键经验（易踩坑）
- `maker_build_current_directory` 工具参数只有 `target_dir/entry/scriptsPath/message/timeout_ms`；**不要**塞 `maxOutputLength`（那是 mcp_call_tool 的参数）等多余字段，否则会 MCP 超时（-32001）。
- `create_video_task` 因视频生成耗时 > MCP 客户端超时，**第一次调用必超时但任务已提交**；紧接着再调一次会报「视频任务并发超限(当前1/1)」并返回 `task_id`；之后用 `query_video_task` 每 120s 轮询到 `succeeded`。并发上限 1/1，多段视频必须串行。
- 视频播放 API：`require("urhox-libs/Video")` → `Video.VideoPlayer{src=..., autoPlay=true, objectFit="contain", onEnded=...}`；`Video.isSupported` 判断平台（仅 WASM）。资源路径用 `assets/video/xxx.mp4`（全量引用模式 `groups:["**"]` 自动入包）。

## 构建/git 同步踩坑（重要）
- 远端有 `sync` 自动提交领先本地时，`maker_build_current_directory` 会「blocked before commit/push」，需先 `git commit` + `git pull --rebase origin main`（用户选择 rebase）再构建。
- `maker_build_current_directory` 首次调用可能 MCP -32001 超时，但 **push 可能已成功、远程构建已后台启动**。不要盲目重试：先 `git status`/`git log origin/main` 确认 push 状态；此时重试会因构建槽占用报 `409 Conflict`。
- 构建成功后 Maker 会再 push 一个 `chore: wake maker build server` 提交，本地会 behind 1；用 `git pull --ff-only origin main` 同步（该 wake 提交含新资源 `.meta` 映射文件）。
- ffmpeg `concat` demuxer 的 `file '...'` 相对路径是相对于**列表文件所在目录**（不是 cwd），列表放 `assets/video/` 时 file 写纯文件名即可，写 `assets/video/xxx.mp4` 会变成 `assets/video/assets/video/...`。

- `audition_voices_for_character` 的 **`candidate_count=3` 必定 MCP -32001 超时**（3 个候选生成耗时 > 客户端超时），且**超时不等于已提交**（查不到任务、assets/audio 空）。**必须设 `candidate_count=1`** 才能同步拿到结果。
- audition 返回 `{success, candidates:[{index, audioUrl, durationSeconds, generatedVoiceId}], recommendedIndex}`；预览音频是远端临时 URL（29s 左右），用 `preview_url` 在 IDE 里直接播放给用户试听。

- **ElevenLabs 安全审核坑**：`character_description` 里出现「儿童具体年龄 + 疾病/脆弱/几乎不说话」等表述会被 403 `blocked_generation` 拦掉（陈雯音前两次均失败）。改成中性「a young female voice, light and gentle」即通过。**audition_line 也要避开窒息/喉咙/死亡等字眼**（周文初稿的「他不配死得那么体面」已改为隐喻版）。
