### 模式 A：过场场景 · 视差三层（⚠️ 已弃用）

每个场景拆成 **3 张图层** 分别出图，运行时以不同速度横向滚动：

| 层 | 视差系数 | 建议宽度 | 内容 | 边缘处理 |
|----|---------|---------|------|---------|
| **背景 BG** | 0.35（慢） | ≈ 0.6×场景总宽 | 天空 / 远景建筑 / 海平线 | 左右自然淡出到纯色 |
| **中景 MID** | 1.0（基准） | = 场景总宽 | 场景主体 + 地面线 + 可交互物件基座 | 标准 |
| **前景 FG** | 1.4（快） | = 场景总宽 | 近景遮挡：栏杆 / 盆栽 / 吊灯 | 左右半透明渐隐避免硬边 |

**统一尺寸**：
- 所有图层高度统一 **1080px**（@1080）
- 地面线固定在中景层 **y = 780px**
- 三层共享同一地平线高度、同一光源方向、同一透视消失点
- 中景层**不画角色**（角色是独立透明立绘叠加）
- 场景总宽建议 **2240px（=2×1120）** 或 **3360px（=3×1120）**

> ⚠️ **已弃用**：office 场景已于 2026-08-26 改为模式 B 多图切换，以下 bg_office_bg/mid/fg 三层视差图不再被任何场景引用，仅作风格参考。

### 模式 B：解密关卡 · 整图切换 · 多屏循环箱庭（★ 核心）

#### 核心概念

参考《塞尔达传说》的箱庭式 dungeon 设计：每个解密关卡由 **N 张独立全屏图片（Screen）** 组成，形成**有向图/环路拓扑**。玩家通过**左右方向按钮**在相邻 Screen 间切换浏览，交互物件（线索点）分散隐藏在各张图片中。

```
示例：线性三屏布局
  [Screen 1] ←→ [Screen 2] ←→ [Screen 3]

示例：环形四屏布局（塞尔达式循环）
  [Screen 1] ←→ [Screen 2]
    ↑           ↓
  [Screen 4] ←→ [Screen 3]
```

#### 整图规格

| 参数 | 值 | 说明 |
|------|-----|------|
| **画幅** | **1920×1080**（16:9 全屏） | 每张 Screen 占满整个游戏画面 |
| **分辨率** | 2K | 出图精度 |
| **透明度** | false（不透明整图） | 每张都是完整场景截图 |
| **地面线位置** | y ≈ 780~820px（画面下方 72%~76%） | 角色站立基准线 |
| **视角** | 侧视横版（side-view） | 与过场场景一致 |

#### 关卡设计原则

1. **每张图都是「完整构图的场景切片」**：不是图层碎片，而是一张可以独立展示的有意义的画面
2. **物件分散隐藏**：关键线索物件不要集中在同一张图，迫使玩家翻页探索
3. **循环/回路**：首尾相连或形成环路，让玩家有「探索完整区域」的满足感
4. **视觉连贯性**：相邻 Screen 的边缘元素应有呼应（如左侧图的右侧柱子 = 右侧图的左侧柱子延续）
5. **每张图都有「看点」**：避免空白填充图，每屏至少含 1 个可交互物件或环境叙事细节

#### 导航 UI 规格

##### 左右翻页按钮（必配）

| 属性 | 规格 |
|------|------|
| **位置** | 屏幕左右两侧垂直居中，距边缘 24px |
| **尺寸** | 48×48px（触控友好） |
| **样式** | 半透明白色箭头（◀ / ▶），圆角方形底板 rgba(0,0,0,0.35)，border-radius 8px |
| **状态** |
| - 默认态：opacity 0.5 |
| - hover 态：opacity 0.85 + 轻微放大 1.1x |
| - 禁用态（到边界）：opacity 0.2，不可点击 |
| **动效** | 按下时左移 2px（左键）/ 右移 2px（右键），松开回弹 |
| **快捷键** | 同时支持键盘 ← / → 方向键翻页（与按钮联动） |

##### 右上角小地图（必配）

| 属性 | 规格 |
|------|------|
| **位置** | 屏幕右上角，距右上角 16px |
| **尺寸** | 140×100px（宽×高） |
| **样式** | 半透明暗色底板 rgba(12,10,20,0.75)，圆角 8px，1px 边框 rgba(255,255,255,0.15) |
| **内容** |
| - 当前关卡的**简化拓扑缩略图**（手绘/极简风格） |
| - N 个节点代表 N 个 Screen，用小方块/圆点表示 |
| - 当前所在 Screen 高亮（金色/橙色标记） |
| - 已探索 Screen 与未探索 Screen 用不同亮度区分 |
| - 相邻节点之间连线表示可达路径 |
| **动态** | 切换 Screen 时，小地图上的高亮标记平滑移动（0.3s 过渡） |

##### 页码指示器（可选增强）

| 属性 | 规格 |
|------|------|
| **位置** | 屏幕底部居中，距底部 16px |
| **样式** | N 个小圆点，当前页为实心白色，其余为半透明白色 |
| **尺寸** | 圆点直径 6px，间距 8px |

**引导原则**：
- **非阻塞式**：所有引导都可被点击/按键跳过，不强制等待
- **渐进式**：一次只教一个操作，不信息轰炸
- **上下文敏感**：只在相关 UI 元素首次出现时触发
- **一次性**：每种引导只播放一次（存档记录引导状态 `tutorial_completed`）
- **视觉焦点**：引导目标元素用脉冲边框/呼吸发光吸引注意力

#### 主角立绘规格（叠加于解密关卡之上）

| 属性 | 值 | 说明 |
|------|-----|------|
| **构图** | 透明背景 PNG，正面/侧面站立全身 | 叠加在场景整图之上 |
| **尺寸** | **约屏幕高度的 55%~65%**（比原 2:3 立绘更大更突出） | 在 1080p 屏幕上约 600~700px 高 |
| **画幅建议** | **800×1200**（2:3 但更大基底）或 **720×1280**（9:16） | 确保 Scene 中足够醒目 |
| **站位** | 脚底对齐地面线（y≈780~820px），水平位置按剧情需要偏移 | 不居中锁定——随剧情在不同 Screen 有不同站位 |
| **朝向** | 正面为主；对话时可微侧身面向对话对象 | 引擎不支持翻转时用不同朝向立绘 |
| **表情差分** | 至少 3 套：普通/认真/惊讶 | 对话系统切换 |

> **重要**：主角在场景中的比例需**明显放大**（占屏幕高度一半以上），确保视觉焦点。不再是远处小人——而是近景叙事级大小，类似参考图中人物与场景的比例关系。
